# Paper Note

# 要約（Abstract）

近年のRAG（Retrieval-Augmented Generation）では、主に埋め込みベクトルにもとづく類似度検索（Dense Retrieval）が用いられてきた。しかし、埋め込みは「テキスト対テキストの静的な類似度」を中心に測るため、プログラミングコード、数値表、会話履歴、実行すべきツール列・エージェント構成など、**明示的な埋め込み空間の近さでは表現しづらい関連**を見落としやすい。そこで本研究は、LLM の報酬モデル（reward model; RM）が出力する**関連度（relevance）スコア**を直接用いて検索する **RMSearch（Reward-Model Search）** を提案する。RMSearch はクエリとキーを同時にRMへ入力し、**文脈依存の非自明な関連性**までとらえる点が従来の内積近似とは異なる。さらに、RM による全対比較は高精度な一方で計算量が O(n^2) と重いという課題に対し、**代表テキストでラベル付けしたグラフ（階層木）上での経路探索**によって、**O(log n)** 程度にまで実用的に抑える手法（RMGSearch）をあわせて提案する。これにより、従来の埋め込み検索では取りこぼしやすかった微妙な関連も拾い上げ、高精度なRAGやエージェント検索への応用が期待できる。

# 1. イントロダクション（Introduction）

## 1.1 背景と課題

RAG は、生成モデルの出力を外部知識の検索結果で補強する枠組みであり、Lewis らのRAGモデル（RAG-Sequence/RAG-Token）によって一般化された【Lewis et al., 2020】。RAG の実装では、検索部に **ベクトル検索（Dense Retrieval）** が広く採用されており、DPR【Karpukhin et al., 2020】や、その後の多様な埋め込みモデルの普及により大規模コーパスから高効率に関連文書を取得できるようになった。一方、埋め込みの品質評価は近年 **MTEB（Massive Text Embedding Benchmark）** の登場で体系化され、分類・クラスタリング・STS・再ランキングなど複数タスクでの汎用性が検証可能になった【Muennighoff et al., 2022/2023】。

しかし、**「クエリとキーを並置して精密に照合する」**という観点では、ベクトル検索だけでは不十分な場面がある。たとえば、

* 同一の意味語彙に依存しない **コード構文や実行手順** の整合、
* **数表・ログ・設定ファイル** の相互参照、
* 過去の **会話履歴／タスク軌跡** と次に実行すべき **エージェント・ツール列** の対応付け、
  などでは、単純なベクトル近傍よりも**文脈依存の「対比較」**が有効となる。

このギャップを埋める一般的な手法が **Reranking（再ランキング）** であり、クロスエンコーダ（monoBERT【Nogueira & Cho, 2019】、monoT5 など）により、**上位k件**の候補を**ペア入力**して高精度に並べ替える。これは実務上きわめて強力だが、「まずベクトル検索で候補を絞る」前提に依存しており、**全コーパスに対してクロスエンコーダを適用する**のは計算コストの観点で非現実的である。

## 1.2 本研究の位置づけ

本研究は、**ベクトル検索に依存しない**「**RMSearch**」という選択肢を提示する。RMSearch は、クエリ q とキー d を **同時にLLMの報酬モデルへ入力**し、**対比較的（pairwise）に関連度 s(q,d) を直接出力**させる。従来のベクトル内積に比べ、**非自明な対応**（例：コーディング規約に基づく実装の一致、グラフ構造を共有する記述、操作手順の前提関係など）の捕捉が期待できる。

ただし、RMSearch を素朴に全件に回すと O(n^2) の計算量となる。そこで我々は、**代表テキストを付与したグラフ（木）インデックス**を構築し、**RM を使った誘導探索**で候補集合を急速に狭める **RMGSearch** を提案する。これは近年注目される GraphRAG の知見【Peng et al., 2024; Han et al., 2024/2025; Zhang et al., 2025】と整合的であり、**Graph-based Indexing / Graph-guided Retrieval** の利点（概念関係・ハブ／コミュニティ構造・階層性の活用）を、**RMによる高精度なノード選別**で強化するものである。

> **関連研究の概観（Overview）**
>
> * **RAG の基礎**：Lewis ら【2020】は、生成モデルに外部メモリを結合するRAGを提案し、検索と生成を統合的に学習する枠組みを提示した。
> * **Dense Retrieval / DPR**：Karpukhin ら【2020】は、質問とパッセージをそれぞれ別のエンコーダで埋め込み、内積で効率に検索する二塔（bi-encoder）を確立した。
> * **MTEB**：Muennighoff ら【2022/2023】は、多様な下流タスク横断で埋め込みを評価する基盤を整備し、**「万能埋め込みは未だない」**ことを示した。
> * **Reranker**：Nogueira & Cho【2019】の monoBERT を嚆矢として、monoT5 等の**クロスエンコーダ**が上位候補の精密並べ替えで顕著な改善を実現してきた。
> * **GraphRAG**：Peng ら【2024】や Han ら【2024/2025】は、知識を**グラフとして索引化**し、**グラフ誘導での検索・生成**を体系化。タクソノミや依存関係を活用して検索の精度・効率を同時に改善しうることを概説した。

## 1.3 本研究の貢献（Contributions）

1. **RMSearch**：クエリとキーを**報酬モデルへ同時入力**し、**文脈依存の関連度**を直接推定する検索手法を定式化。
2. **RMGSearch**：代表テキストで注釈した**グラフ（階層木）インデックス**上で RM による**誘導探索**を行い、**O(n^2) → ~O(log n)** まで計算量を実用域に圧縮する近似全探索法を提案。
3. **応用示唆**：コード検索、エージェント（ツール列）選択、会話メモリ検索、数表・設定ファイル照合など、**埋め込み近傍に収まりにくい関連**を要するRAG/Agent 系タスクへの有効性を概念実証レベルで示す。

## 1.4 評価の要約（Summary of Evaluation Results）

本稿では RMSearch/RMGSearch の**設計・理論的根拠**と**評価設計**を提示する。詳細な数値は別節に譲るが、一般的なベクトル検索→Rerank の二段構えと比較し、**コーディング関連・依存手順・テンプレート整合**を含むケースで一貫した再現性ある改善傾向を観察している（データセット・設定の詳細と指標は最終版で報告）。

# 2. アプローチ（Approach）

## 2.1 概要（Overview）

埋め込み検索は**高速・可換**（内積）という利点を持つ一方、**「q と d を並置して読む」**能力がない。対して RMSearch は、**q と d を同時に RM へ与えて**関連度を得るため、**前提関係や手続き的依存**などの**非自明な結び付き**を検出できる。しかし素朴な全件比較は O(n^2) と重い。そこで、本研究は以下の三段階を提案する：

1. **(2.2) RMSearch**：RM を用いた高精度な対比較スコアリング。
2. **(2.3) RMGSearch**：グラフ（階層木）上での代表ノード経由の探索により計算量を実用域に削減。
3. **(2.4) リアルタイム更新**：運用中に追加されるノード／エッジやドリフトに合わせて**代表テキストと経路**を**逐次更新**し、検索品質と計算量バランスを維持。

## 2.2 RM による検索（RMSearch）

RMSearch は、**クエリ q とキー d を同一のトランスフォーマ・アーキテクチャへ同時入力**し、**関連度 s(q,d)** を**スカラー**として出力させる（これはベクトル検索における**内積に相当する基本操作**に対応するが、計算実体は**クロスアテンションに基づく文脈照合**である）。アーキテクチャ的には **Reranker（クロスエンコーダ）** と同様だが、**「候補上位のみ」ではなく**、**可能な限り広い集合**に対して適用する点が異なる。計算量は、クエリ数とキー数の双方を n のオーダとすると **O(n^2)** に増大するため、単独での全件適用はスケールしない。

**直観的効果の例**：

* **コード検索**：q が「ビット演算でフラグを落とす方法」で、d が具体的な `mask &= ~FLAG;` を含むスニペット。語彙一致が弱くても、RM は**操作意味**の一致を学習していれば高得点を付けやすい。
* **手順整合**：q が「A→B→C の順で初期化」と述べるとき、d が「B を先に行う」と書くドキュメントを**低く**、順序一致の d を**高く**評価できる。

## 2.3 グラフ併用による高速化（RMGSearch）

RMSearch の精度を保ちながら計算量を抑えるため、**代表テキスト（タグ）を付与したグラフ／階層木**をインデックスとして構築する。各ノードは**サブコーパスの「代表記述」**（短い説明・要約・模式例）を保持し、エッジは**トピック的近接や前提関係**を表す。照会時には：

1. ルートから開始し、**q と各子ノード代表テキスト**を RM に同時入力して**分岐先を選別**する（ビーム幅は小）。
2. 選別した分岐のみを**再帰的に下る**（階層木なら深さは log n 程度）。
3. 葉または浅いサブ木に到達したら、その**局所集合**に対して RM を適用し**精密比較**する。

この**RMによる誘導探索**は、GraphRAG の「Graph-based Indexing / Graph-guided Retrieval」の一般形に沿う。Peng ら【2024】は **Text-Attributed Graph (TAG)** の形式で、Han ら【2024/2025】は**グラフ構築・誘導・生成**のワークフローを整理している。本研究は代表テキストの設計を**RM のスコア分離能が高まるよう最適化**（短く、区別的特徴を強調）し、**誤誘導時のバックトラック**と**ビーム再拡張**を組み合わせて堅牢性を確保する。理想化すれば探索深さは **O(log n)**、局所精密比較も小規模で済むため、実運用での待ち時間を大きく削減できる。

## 2.4 リアルタイム更新（Realtime Update）

運用下ではデータとクエリ分布が変化する。RMGSearch では、以下を**オンライントリガ**で実行し、**品質とスループットの両立**を維持する：

* **（代表テキストの再学習）**：新規ノード・ドキュメントが一定数追加／既存ノードの分散が増大した場合、**短文ボイラープレート＋差分要約**で代表テキストを更新。RM の分離能を測る**情報利得指標**（代表文を用いた分岐のスコア間隔）で更新可否を判断する。
* **（階層のリバランス）**：子ノードの負荷不均衡が閾値を超えたとき、**二分木化や再クラスタ**で**平均分岐度を一定**に保つ（探索深さ≒log n を維持）。
* **（誤誘導検知と自己修復）**：検索ログで**終端付近の再探索率**や**バックトラック頻度**が増えた場合、原因ノードを特定し代表テキスト・エッジ重み・分岐順序を**局所更新**する。

# 3. 関連研究（Related Work）

**RAG**：外部知識を検索で取り込みつつ生成を行う統合枠組みとして Lewis ら【2020】が提案。以降、多数の拡張や調査がある（例：包括的サーベイ）。

**Dense Retrieval / DPR**：Karpukhin ら【2020】以降、二塔エンコーダや負例マイニング等の技術が確立し、多様なコーパスでの高速検索の標準となった。

**Reranking**：monoBERT【Nogueira & Cho, 2019】、monoT5 系などの**クロスエンコーダ**は、上位候補を**対比較**で精密に並べ替え、大幅な精度向上を実現。ただし計算量の観点から**全件適用**は困難で、通常は retriever の**上位k**に限定される。

**GraphRAG**：Peng ら【2024】や Han ら【2024/2025】、Zhang ら【2025】が、グラフ索引・グラフ誘導検索・グラフ強化生成の体系を整理。本研究の RMGSearch は、**代表テキスト×RM** による**分岐の識別性向上**と**計算量の対数スケール化**で、これらの潮流を実装上の戦術に落とし込む。

---

# 4. まとめと展望（Conclusion & Outlook）

本稿は、**ベクトル検索に依存しない**新たな検索選択肢として **RMSearch** を提案し、計算量の課題を **RMGSearch**（グラフ誘導）で緩和する設計を示した。今後は、

* 公開データ（コード検索・手順整合・会話メモリ検索）での**再現可能なベンチマーク**整備、
* MTEB 系指標に加え、**因果・前提・手続き**に敏感な**RM特有の評価軸**の策定、
* 代表テキスト自動生成の**蒸留・自己改善**（distillation / self-improvement）、
  を進める。これにより、RAG/Agent 系システムで**“取りこぼさない検索”**を標準化することを目指す。
